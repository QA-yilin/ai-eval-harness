# AI 任务调度平台架构设计

## 一、为什么需要调度平台

Harness 是单机执行框架，能跑四类评测任务，但无法满足规模化评测需求。六个瓶颈：

| 瓶颈 | 现状 | 需要的能力 |
|------|------|-----------|
| 手动触发 | python run.py 手动跑 | 定时/事件触发 |
| 单机执行 | 单进程串行 | 多 worker 并发 |
| 结果本地 | 写本地目录 | 入库 + 查询 + 可视化 |
| 无告警 | 失败靠自己看 | 失败通知 + 重试 |
| 无成本追踪 | 不知道花了多少 | API 费用统计 |
| 无 CI 集成 | 手动跑评测 | 合并前自动跑 |

核心公式：调度平台 = Harness（执行单元）+ 任务管理 + 资源调度 + 结果存储 + 监控告警。

## 二、整体架构（六层）

| 层 | 职责 | 关键组件 |
|----|------|---------|
| 接入层 | 用户入口 | Web UI / CLI / API / Webhook / CI-CD |
| 任务层 | 任务管理 | 任务注册 / 编排 / 依赖 / 版本 |
| 调度层 | 决定何时何地跑 | 调度器 / 队列 / 优先级 / 并发 / 限流 |
| 执行层 | 实际跑 Harness | Worker Pool / Docker 隔离 / 重试 |
| 存储层 | 数据持久化 | 任务元数据 / 结果 / 配置快照 / 日志 |
| 监控告警层 | 可观测性 | 指标看板 / 失败告警 / 趋势 / 成本 |

## 三、核心模块设计（6 个）

### 3.1 任务注册（Task Registry）

管理所有可执行的评测任务。

| 字段 | 说明 |
|------|------|
| task_id | 任务唯一标识 |
| task_type | rag-layered / judge-calibration / agent-trajectory / prompt-injection |
| dataset | 数据集名 |
| model | 模型名 |
| evaluators | 评测器列表 |
| priority | 优先级 |
| timeout | 超时 |
| retry | 重试次数 |

实现：读 config/tasks.yaml，注册到 DB。

### 3.2 调度器（Scheduler）

决定「什么时候、哪个任务、在哪个 worker 上跑」。

三种触发方式：
- 定时：每天凌晨跑一次全量评测
- 事件：代码合并 / 模型更新 / 数据集更新
- 手动：Web UI / CLI 手动触发

调度策略：FIFO / 优先级队列 / 资源感知。

技术选型：

| 方案 | 优点 | 缺点 |
|------|------|------|
| Celery | 成熟、生态好 | 需 Redis/RabbitMQ |
| Airflow | DAG 编排强 | 重，适合批处理 |
| 自研 | 可控 | 工作量大 |

推荐：Celery + Redis。

### 3.3 执行层（Worker Pool）

每个 worker 的职责：
1. 从队列取任务
2. 拉起 Harness（python run.py --task xxx）
3. 采集结果（读 results/<run_id>/）
4. 上报结果到存储层
5. 上报指标到监控层

资源隔离：Docker 容器 + 资源配额 + 超时强杀。
失败重试：网络失败重试 3 次，模型失败标记，超时强杀。

### 3.4 存储层（Storage）

| 类型 | 存储 | 说明 |
|------|------|------|
| 任务元数据 | PostgreSQL | 任务状态、配置、依赖 |
| 结果数据 | 对象存储（S3/OSS） | raw_results / reports |
| 配置快照 | DB + 对象存储 | 双写，保证可复现 |
| 日志 | ELK / Loki | 结构化日志 |
| 指标 | Prometheus | 时序指标 |

关键设计：
- 结果数据不可变（append-only）
- 每次运行独立 run_id
- 配置快照和结果一起存

### 3.5 监控告警层

监控指标：

| 指标 | 用途 |
|------|------|
| 任务成功率 | 健康度 |
| 平均执行时长 | 性能 |
| 队列长度 | 容量 |
| 失败率 | 质量 |
| Kappa 趋势 | 评测可信度漂移 |
| API 成本 | 费用 |

告警规则：
- 任务失败 → 钉钉/飞书通知
- Kappa < 0.6 → 警告
- 防御成功率 < 95% → 阻断
- 队列积压 > 阈值 → 扩容告警

### 3.6 CI/CD 集成

把评测嵌入研发流程，代码合并前自动跑评测。

两种集成方式：

| 方式 | 说明 | 适用 |
|------|------|------|
| CI 直接调 Harness | CI 机器跑 run_all.py | 轻量、小团队 |
| CI 调平台 API | CI 触发平台任务 | 规模化 |

推荐流程：
PR 提交 → CI 触发 → 调平台 API 创建任务
→ 平台调度 → Worker 跑 Harness
→ 结果入库 → CI 轮询任务状态
→ 门禁检查 → 通过/阻断

关键设计：
- 门禁指标放 config/gates.yaml
- CI 只负责触发和检查，不负责执行
- 结果入库，PR 上能看到评测报告链接
- 失败自动通知到 PR 评论

## 四、补充模块（8 个，简写）

### 4.1 权限（RBAC）

内部平台需要角色：谁跑评测、谁看结果、谁改配置。不需要多租户（那是 SaaS 的）。

### 4.2 成本管理

- 每次运行的 API 调用次数、token 数、费用
- 按任务/模型/团队分摊
- 成本趋势 + 预算告警

### 4.3 数据管理

- 数据集注册（golden set / corpus / 注入用例）
- 数据集版本管理
- 训练集/评测集隔离

### 4.4 模型管理

- 模型注册（DeepSeek / Ollama / 其他）
- 模型版本管理
- 模型路由（按任务选模型）

### 4.5 结果分析

- 趋势分析（Kappa 随时间变化）
- 跨 run 对比
- 归因分析（哪个 case 变化了）

### 4.6 告警通道

- 多渠道：钉钉 / 飞书 / 邮件 / Webhook
- 分级：P0 电话 / P1 钉钉 / P2 邮件

### 4.7 安全

- 密钥管理（Vault / KMS）
- 数据脱敏（PII 不进日志）
- 审计（谁在什么时候跑了什么）
- 注入测试沙箱

### 4.8 可观测性

- 日志（结构化、可查询）
- 指标（Prometheus）
- 链路追踪（trace_id 贯穿）
- 看板（Grafana）

## 五、和 Harness 的关系

| 层 | 职责 | 产物 |
|----|------|------|
| 调度平台 | 任务管理 + 调度 + 存储 + 监控 | 任务状态、指标看板 |
| Harness | 执行单元 | run 目录、配置快照、报告 |

核心：Harness 是执行单元，平台是管理系统。平台调度多个 Harness 实例。

## 六、关键设计决策

| 决策 | 原因 |
|------|------|
| 用队列而不是直接调用 | 解耦触发和执行 + 削峰 + 可观测 |
| 结果要入库 | 查询历史 + 跨 run 对比 + 异常告警 |
| 配置要快照 | 可复现 + 审计 + 回滚 |
| 用 Docker 隔离 | 环境一致 + 资源隔离 + 安全 |
| CI 调平台 API 而非直接跑 | 资源隔离 + 结果入库 + 统一调度 |

## 七、演进路线

| 阶段 | 能力 | 说明 |
|------|------|------|
| L1 | 单机 Harness | 已完成 |
| L2 | 任务队列 + 多 worker | 并发执行 |
| L3 | 结果入库 + 查询 | 历史可追溯 |
| L4 | 监控告警 + CI/CD | 异常自动发现 |
| L5 | 成本管理 + 数据/模型管理 | 精细化运营 |
| L6 | 智能调度 | 按成本/延迟优化 |

当前在 L1，文档设计到 L4。

## 八、面试话术

> "Harness 是单机执行框架，能跑四类评测，但规模化不够——手动触发、单机执行、结果本地。所以我设计了 AI 任务调度平台：接入层（Web/CLI/API/CI-CD）、任务层（注册/编排）、调度层（队列/优先级）、执行层（Worker Pool/Docker 隔离）、存储层（DB + 对象存储 + 配置快照）、监控告警层（指标看板 + 失败通知）。
>
> 核心设计是 Harness 作为执行单元，平台负责调度和存储。技术选型推荐 Celery + Redis + PostgreSQL + S3 + Prometheus。演进路线从 L1 单机到 L6 智能调度，当前 Harness 在 L1，文档设计到 L4。"

## 九、一句话

调度平台 = Harness（执行单元）+ 任务管理 + 资源调度 + 结果存储 + 监控告警。六层架构 + 6 个核心模块 + 8 个补充模块。核心决策：队列解耦、结果入库、配置快照、Docker 隔离、CI 调平台 API。
